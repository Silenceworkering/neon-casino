# NEON CASINO

Социальная веб-платформа исключительно с виртуальными NC и CRYSTALS. Без реальных денег, депозитов, вывода, криптоплатежей и денежных призов.

Реализован запускаемый проект на React 19, TypeScript, Vite, Tailwind CSS, Framer Motion, Express, Socket.IO, PostgreSQL и Prisma. Frontend и backend обслуживаются одним Node-сервисом и одним публичным адресом.

## Что работает

- Регистрация, bcrypt, серверные сессии в HttpOnly cookies, никнейм, гостевой режим, восстановление по одноразовому коду с ротацией и отзывом сессий.
- Постоянный кошелёк, 10 000 NC при регистрации, журнал всех операций, serializable-транзакции, блокировки пользователя, уникальные ключи повторов, ограничения БД от отрицательных остатков.
- 18 одиночных режимов: пять тематических Slots с отдельными таблицами; Roulette; Blackjack; Mines; Crash; Plinko; Dice; Coinflip; Limbo; Hi-Lo; Tower; Fortune Wheel; Case Opening; Draw Poker; Baccarat; Keno; Memory; Daily Challenge.
- Ещё два режима для настоящих участников: Jackpot и Battle; Draw Poker также работает на 2–6 игроков в комнате. В комнатах нет ботов и искусственных участников. Сервер списывает одинаковые ставки и распределяет весь банк без комиссии.
- Сохранённые комнаты и раунды, вход по коду, приглашения друзьям, присутствие, автоматическое переподключение, история матчей. Poker автоматически завершается через 120 секунд при пропуске хода.
- Профиль, XP, уровни, достижения, коллекция, рамки, аватары, кристальный магазин. Daily/weekly бонусы, ежедневное колесо, задания, промокоды, бесплатный пропуск, события, престиж.
- Друзья, поиск, принятие/отмена запросов, уведомления. Реферальная рамка после пяти игр приглашённого друга; валюта за приглашение не выдаётся.
- Рейтинги, бесплатные турниры по XP и однократная выплата CRYSTALS победителю после окончания.
- Администратор: пользователи, блокировки, начисления, промокоды, события, турниры, параметры экономики, журнал действий и последние операции.
- Русский адаптивный интерфейс, боковая навигация на ПК и нижняя на телефоне, настройки звука/эффектов, reduced motion, облегчённый режим.

## Чёткие границы версии

Это рабочая первая версия, а не завершённая реализация каждого пункта исходного большого ТЗ. Покер — **пятикарточный Draw Poker с одним обменом и без торгов**, не Texas Hold'em. Blackjack не включает split и insurance. Crash — индивидуальный серверный раунд с автовыводом, не глобальный общий поток. Plinko использует дискретную модель Галтона с анимацией пути, не непрерывный физический движок. В кейсах выдаются NC, коллекционные вещи покупаются отдельно за заработанные CRYSTALS. Аватары — встроенные emoji, загрузки пользовательских изображений нет. Звуки синтезируются локально Web Audio.

Новости первого сезона встроены в интерфейс; события управляются через админку. В этой версии нет чата, email-рассылок, редактирования/удаления существующих событий через UI, развитой системы антифрода/автоматического расследования, полноценного редактора сезонов, экспорта/удаления аккаунта через личный кабинет и длительных нагрузочных испытаний. Админка показывает журнал операций для ручной проверки. Рейтинги вычисляются по запросу, турниры завершаются фоновой задачей и при старте сервиса.

Нативные проверки в Chromium не заменяют тестирование на физических Android/iPhone. Рейтинги показывают XP, число достижений, размер коллекции, игры за неделю, лучший результат Memory и число побед в турнирах.

## Быстрый запуск с Docker

Нужен Docker с Compose:

```sh
docker compose up --build
```

Откройте `http://localhost:3000`. База сохраняется в именованном томе `neon-data`. Не удаляйте этот том, если хотите сохранить аккаунты. Локальный пароль Compose предназначен только для разработки; PostgreSQL привязан к localhost.

## Запуск без Docker

Нужны Node.js 22.12+ (рекомендуется 24), npm и постоянная PostgreSQL 17+.

```sh
npm ci
cp .env.example .env
# В .env укажите DATABASE_URL вашей PostgreSQL.
npm run db:migrate
npm run db:seed
npm run build
npm start
```

Откройте `http://localhost:3000`. Во время разработки: `npm run dev` и в другом терминале `npm run dev:client`. Для Vite укажите `APP_URL=http://localhost:5173`, чтобы same-origin защита разрешала проксированные запросы с Vite. В production разрешается ровно один канонический адрес `APP_URL`; на Render автоматически используется `RENDER_EXTERNAL_URL`.

Создайте обычный аккаунт и сохраните показанный код восстановления. Пароль игрока — минимум 10 символов.

### Отдельный вход администратора

Панель доступна по `/admin` (на опубликованном сайте: https://neon-casino-sjrb.onrender.com/admin). Отдельная форма проверяет логин, пароль и серверную роль `ADMIN`. Обычный аккаунт в панель не допускается.

В Render откройте сервис → **Environment → Add Environment Variable**, добавьте обе переменные и сохраните с перезапуском:

- `ADMIN_LOGIN`: отдельный логин администратора, 3–20 букв/цифр/подчёркиваний, например `NeonOwner`.
- `ADMIN_PASSWORD`: ваш собственный секретный пароль длиной от 16 символов (до 72 байт UTF-8). Не отправляйте его в чат и не коммитьте в Git.

При запуске сервер создаёт администратора с хешем bcrypt. Если такой логин уже принадлежит обычному игроку, выберите другое имя: права существующего игрока автоматически не повышаются. Повторный запуск не дублирует аккаунт. Изменение `ADMIN_PASSWORD` обновляет хеш и отзывает предыдущие сессии; вход через `/admin` действует 8 часов. Без этих двух переменных новый администратор не создаётся; существующие администраторы могут входить со своим паролем.

Для локального запуска те же переменные можно добавить в игнорируемый `.env`. Также сохранена CLI-команда назначения роли существующему аккаунту: `npm run admin -- ВашНикнейм`, доступная только владельцу подключения к базе.

## Render и постоянная база

`render.yaml` создаёт один web-сервис с `plan: free`. **Публикация не выполнена. Доступ к Render отсутствовал; официальная страница тарифов заблокирована сетевой политикой среды. Актуальность бесплатных тарифов на 15.10.2026 не подтверждена.** Проверьте условия перед созданием ресурсов:

- https://render.com/docs/free
- https://render.com/pricing
- https://neon.com/pricing — возможный внешний управляемый PostgreSQL
- https://supabase.com/pricing — ещё один вариант

Не выбирайте базу с автоматическим удалением по истечении пробного периода. В этой конфигурации Render-база специально не создаётся: введите `DATABASE_URL` внешней постоянной PostgreSQL с TLS. Следуйте строке подключения провайдера; TLS-проверка не отключается. Бесплатные предложения внешних провайдеров тоже нужно проверить на срок хранения, паузы, лимиты и резервные копии.

После загрузки репозитория `neon-casino`:

1. Откройте Render → New → Blueprint и выберите этот репозиторий.
2. Подключите PostgreSQL: вставьте `DATABASE_URL` в секретную переменную. `IP_HASH_SECRET` Render генерирует автоматически.
3. Проверьте в интерфейсе Render, что выбран именно бесплатный план и не добавлены платные ресурсы. Запустите Blueprint.
4. Сборка: `npm ci --include=dev && npm run build`. Старт: `npm run db:migrate && npm start`. Проверка здоровья: `/api/health` с запросом к базе.
5. Дождитесь статуса Live и успешного health check. Только затем отправляйте друзьям адрес вида `https://neon-casino-....onrender.com`.
6. Зарегистрируйтесь, сохраните код восстановления и назначьте админа указанной выше командой.

Если сервис засыпает, первое открытие будет медленным, а WebSocket переподключится. Все игровые состояния, авторизация, балансы, операции и комнаты хранятся в PostgreSQL. При простое турниры рассчитываются после пробуждения. Crash автовывод рассчитывается при следующем обращении к активному раунду. Важных данных в файловой системе Render нет. Счётчики rate limiting и присутствие работают в памяти одного экземпляра; архитектура рассчитана на один экономный web-сервис. Для горизонтального масштабирования нужны Redis rate limit/Socket.IO adapter и отдельный план фоновых задач.

Миграции выполняются при старте, потому что бесплатный Render может не предоставлять pre-deploy command. Не запускайте одновременно несколько сервисов с этим startCommand. Регулярно делайте резервные копии базы у её провайдера, проверьте восстановление до приглашения большой группы.

## Проверки

В `.github/workflows/ci.yml` подготовлен GitHub Actions: PostgreSQL 17, сборка, применение миграций, интеграционные тесты и браузерный smoke test. Результат удалённого workflow проверяется отдельно во вкладке Actions.

```sh
npm run check
npm run build
npm test
```

`npm test` без `TEST_DATABASE_URL` запускает только проверки игрового движка и явно сообщает, что интеграционные проверки пропущены. Для полного набора создайте **отдельную** PostgreSQL-базу с именем, заканчивающимся на `_test`:

```sh
TEST_DATABASE_URL=postgresql://user:password@localhost:5432/neon_test npm test
```

Тесты удаляют и создают схему **только указанной тестовой базы**. Никогда не используйте рабочую базу. Проверяются авторизация, секреты, транзакции, повторы и параллельные запросы, бонусы, промокоды, покупки, друзья, права администратора, турниры, реальный обмен Socket.IO, сохранение общего банка и переподключение.

Для браузерной проверки запустите приложение с `APP_URL=http://localhost:3000` и Chromium:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Проверка создаёт тестовый аккаунт в подключённой базе, играет Coinflip и получает daily bonus. Не запускайте на production. Скриншоты сохраняются в игнорируемую папку `artifacts/`. Проверяются ширины 320, 375, 390, 768, 1024, 1440, регистрация, игра, профиль, настройки, бонусы, сохранение после reload и отсутствие ошибок JS.

## Безопасность и экономика

- Клиент не передаёт результат или новый баланс. Параметры проверяются Zod; Prisma использует параметризованные запросы. React экранирует пользовательский текст, Helmet задаёт CSP. Cookie HttpOnly/SameSite=Lax/Secure в production, мутации проверяют Origin и Content-Type. Auth endpoints имеют отдельные лимиты.
- Каждая ставка, выплата и бонус проходят атомарную транзакцию. `WalletTransaction(userId,key)` и `GameSession(userId,key)` уникальны. При конфликте сериализации транзакция повторяется. Баланс ограничен целочисленным диапазоном; одиночная выплата не более 1 000 000 NC.
- Криптографический seed — 32 случайных байта `node:crypto`. HMAC-SHA256 даёт воспроизводимый поток с rejection sampling. Никаких персональных корректировок вероятностей. Seed скрыт до окончания; опубликованный после игры хеш позволяет проверить воспроизводимость, но не является полным протоколом provably fair с предварительным выбором client seed.
- Скрытые карты, мины, колода и точка Crash удаляются из ответов до завершения. Активные сессии доступны только владельцу. WebSocket проверяет сессию, блокировку, членство комнаты и лимиты на каждом действии.
- До трёх регистраций/гостевых сессий на хеш IP в сутки; записи старше семи дней удаляются. Это базовая защита, а не гарантия против распределённого Sybil-ботнета. Значимых наград за повторные приглашения нет: только одна косметическая рамка.
- Коды восстановления одноразовые; исходный пароль и recovery code в БД не сохраняются. Восстановление отзывает все сессии. Без кода требуется помощь владельца проекта.
- Начисления админа журналируются. Назначение первого админа — только CLI с доступом к базе.

## Структура

```text
client/                 React, дизайн, каталог, игровые экраны
server/index.ts         HTTP API и production static hosting
server/auth.ts          Сессии и права
server/db.ts            Атомарный кошелёк и транзакции
server/games.ts          Все одиночные игровые алгоритмы
server/economy.ts        Награды, XP, достижения, задания
server/rooms.ts          Сохранённый Socket.IO-мультиплеер

scripts/                Админ, локальное тестирование и QA
tests/                  Движок и интеграционные тесты
render.yaml             Один Render web-service
```
